# 重放与认证审计

## 先按协议分组

Trojan、VLESS、Shadowsocks 2022、VMess、QUIC 和各 TLS 伪装方案的认证材料与重放语义不同。先确认目标协议、会话范围、密钥范围和实现中的状态容器，再决定是否需要跨连接记忆。

## 审计步骤

1. 标记认证材料生成、传输、校验、消费和失效的时间点。
2. 确认 nonce、salt、计数器或时间戳在协议规定的作用域内满足唯一性和窗口要求。
3. 检查认证失败在拨号、写入状态和启动业务流量前返回。
4. 检查重连、并发、进程重启、时钟偏移、缓存过期和内存上限。
5. 检查 salt/nonce 记忆容器的淘汰、锁定、allocator 和关闭生命周期。
6. 检查错误响应不会泄露认证结果细节，也不会被错误地转成开放回落。

## 约束

- 时间窗口必须来自协议、配置或现有实现，不能统一写死 72 小时。
- 只对确实需要跨会话去重的协议维护历史状态；会话 nonce 不应被无依据地持久化。
- 先验证协议规定的 tag、长度和派生结果，再判断是否接受请求。
- 防重放缓存必须有容量和过期策略，不能用无界容器。

## 验证

每个受影响协议至少覆盖首次请求、重复请求、过期材料、未来时间、错误 tag、重连和并发重复。优先使用 golden vector、互操作测试和协议错误矩阵。
