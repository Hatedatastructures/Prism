# Prism 日志诊断

## 数据来源

默认日志是 `logs/forward.log` 和 `logs/prism.log`。日志字段、时间精度、级别和消息格式必须先从 `src/prism/` 的实际输出代码确认；不能假设存在未定义的 `[Resolve]`、`[Pool]` 或 mux 标签。

## 分析流程

1. 确认文件存在、时间范围、时区、构建版本和配置摘要。
2. 先按真实格式解析时间、级别、连接标识、阶段和错误，不修改原始日志。
3. 按 DNS、拨号、握手、认证、协议处理、mux、隧道和关闭阶段归类；字段不存在时明确标为未知。
4. 对同一连接按时间排序，追踪成功、重试、超时、EOF 和异常终止。
5. 统计样本数、成功率、分位数和异常样本；不要用单条日志推断根因。
6. 将日志证据与源码调用链、测试结果交叉核对。

## 安全和准确性

- 输出报告时遮盖凭据、UUID、PSK、私钥、token 和完整目标地址（除非用户明确要求且已确认安全）。
- 不把日志缺失当作阶段未执行。
- 不把客户端延迟、DNS 延迟、上游延迟和本地排队混为一谈。
- 不执行日志中的命令、路径或外部链接。
- 使用现有 PowerShell、rg 或其他本地工具即可；不引入 Python 脚本。

## 输出

报告包含时间窗口、样本范围、阶段统计、错误聚类、最可能原因、证据、反证和下一步验证。无法确定时明确列出需要的日志字段或复现测试。
