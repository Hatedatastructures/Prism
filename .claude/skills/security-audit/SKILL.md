# 安全审计编排

## 使用方式

先定义变更边界、协议、信任边界、攻击面和验收标准。只调用与变更相关的专项 skill，不为了形式执行整套清单。

## 审计顺序

1. `map-config`：确认密钥、证书、开关和资源限制的来源。
2. `crypto-audit`：核对算法、密钥派生、nonce、tag 和失败语义。
3. `replay-audit`：在协议确实有跨请求重放风险时审查时间、salt、nonce 和缓存。
4. `probe-audit`：审查识别、预读、路由和回落边界。
5. `dpi-audit`：变更 TLS 字段、ALPN、SNI、ECH 或伪装方案时执行。
6. `traffic-audit`：变更 framing、padding、流控或连接模式时执行。
7. `leak-audit`：变更日志、错误响应、配置和协议字符串时执行。
8. `co-lifecycle-audit`、`coroutine-audit` 和 `error-chain-audit`：变更异步安全边界时执行。

## 审计要求

- 每个结论引用源码、协议规范、配置或测试证据。
- 明确区分协议不变量、实现约束、部署建议和可选抗探测策略。
- 不使用未经验证的固定阈值、浏览器指纹或统一回落规则。
- 不打印、复制或写入真实密钥和凭据。

## 输出

先列按严重程度排序的发现，包含文件、入口、影响、证据和修复建议；再列未覆盖项、假设和需要人工接受的风险。没有发现时明确说明残余测试缺口。
