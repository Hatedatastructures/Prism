# 信息泄漏审计

## 审计范围

检查密码、UUID、PSK、私钥、token、会话材料、目标地址、内部路径、异常栈、版本标识和协议实现细节。先确认数据是否真的可到达日志、客户端、上游或配置文件。

## 审计步骤

1. 沿输入、解析、错误、日志、响应和配置序列化路径追踪敏感字段。
2. 检查成功、失败、认证拒绝、超时、异常和 debug 日志级别。
3. 检查原始请求、密钥材料、完整 URL、内部文件路径和栈信息不会被无意输出。
4. 检查错误响应遵守目标协议，不用不安全的统一回落替代错误语义。
5. 检查 `src/configuration.json` 只包含示例值，不加入真实凭据或本机路径。
6. 检查脱敏是否保留足够的连接标识用于诊断，且不会破坏日志关联。

## 重要边界

- 配置中的密码、UUID、PSK 和私钥是否需要哈希，必须按对应协议判断。
- 不把所有字符串都删除；协议标准字段和必要诊断信息可以保留。
- 不为隐藏泄漏而改变认证、证书验证或标准错误响应。
- 日志报告、测试 fixture 和 benchmark 输出同样需要检查。

## 验证

搜索新增日志和响应路径，使用错误矩阵测试确认敏感输入不会回显。报告列出字段、暴露面、严重程度、脱敏方案和对诊断能力的影响。

## 相关 Skill

配置见 `map-config`，错误传播见 `error-chain-audit`，认证见 `replay-audit`，TLS 观测见 `dpi-audit`。
