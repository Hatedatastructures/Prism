# 模块分析

## 适用范围

用于分析、记录或重构当前 Prism 模块。生产公共头位于 `Include/Prism/`；实现、私有头和模块 CMake 位于 `Src/Prism/`；对应功能测试位于 `Test/Prism/`。先按 `AGENTS.md` 的模块所有权确定 owner，并同时核对源码 include 方向与 CMake target 依赖。默认输出到用户指定位置；未指定时优先更新仓库 `docs/` 中已有的相关文档，不写入外部盘符或私人 wiki。

## 分析流程

1. 读取 `AGENTS.md`、目标模块公共接口、对应 `Src/Prism/` owner 与模块 CMake、相邻测试。
2. 若仓库存在 `.codegraph/`，先用 CodeGraph 定位符号和调用链；否则使用 Glob/Grep 和定向读取。
3. 识别模块职责、入口、依赖方向、资源所有权、异步边界、配置和错误模型。
4. 从真实调用点确认运行路径，不按目录名猜测架构。
5. 列出不变量、故障模式、扩展点、已知技术债和测试证据。
6. 分开报告生产代码、测试设施、实验用例和规划材料；不把实验测试当作生产验收。
7. 需要重构时先给出最小边界和验证方案，再修改代码。

## 文档要求

- 所有路径、符号和命令可在当前仓库找到。
- 不把已退役的旧路径、历史报告或旧 API 当作当前事实。
- 不把 TODO、历史计划或旧 wiki 当作当前事实。
- 对推断明确标注证据和不确定性。
- 流程图遵循 `draw-flowchart`。

## 输出

模块结论应包含职责、调用链、数据与所有权、错误和取消、配置、测试、变更敏感区和未确认问题。只在用户要求时创建或更新文档。
