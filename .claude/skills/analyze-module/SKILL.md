# 模块分析

## 适用范围

用于 `include/prism/`、`src/prism/`、`preview/`、`tests/` 及其对应配置和文档。默认输出到用户指定位置；未指定时优先更新仓库 `docs/` 中已有的相关文档，不写入外部盘符或私人 wiki。

## 分析流程

1. 读取 `AGENTS.md`、模块聚合头、公共接口、实现 CMake 和相邻测试。
2. 若仓库存在 `.codegraph/`，先用 CodeGraph 定位符号和调用链；否则使用 Glob/Grep 和定向读取。
3. 识别模块职责、入口、依赖方向、资源所有权、异步边界、配置和错误模型。
4. 从真实调用点确认运行路径，不按目录名猜测架构。
5. 列出不变量、故障模式、扩展点、已知技术债和测试证据。
6. 需要重构时先给出最小边界和验证方案，再修改代码。

## 文档要求

- 所有路径、符号和命令可在当前仓库找到。
- 区分生产实现、preview 实现、测试设施和规划文档。
- 不把 TODO、历史计划或旧 wiki 当作当前事实。
- 对推断明确标注证据和不确定性。
- 流程图遵循 `draw-flowchart`。

## 输出

模块结论应包含职责、调用链、数据与所有权、错误和取消、配置、测试、变更敏感区和未确认问题。只在用户要求时创建或更新文档。

## 相关 Skill

文档深度见 `deepen-wiki`，生命周期见 `co-lifecycle-audit`，测试评估见 `review-test`。
