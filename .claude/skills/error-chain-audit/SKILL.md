# 错误链审计

## Prism 错误边界

- 网络和协议热路径优先使用 `fault::code`，避免异常控制正常流。
- 启动配置、依赖初始化和不可恢复故障可以通过 `exception::deviant` 及其派生层次传播。
- 后台或 detached 任务必须有明确的 completion/error 处理策略，不能静默丢异常。

## 审计步骤

1. 从底层错误源追踪到 API、协程边界、日志和用户响应。
2. 检查错误码是否保留了必要原因，转换时没有把不同故障错误合并成错误成功。
3. 检查每个 `co_spawn` completion handler、异常捕获和取消路径。
4. 检查部分写入、EOF、timeout、operation_aborted 和 socket close 的语义。
5. 检查日志上下文是否足够定位问题，同时去除凭据、密钥、完整 token 和原始认证数据。

## 不做的假设

- 不要求所有错误都继续运行；启动阶段的致命错误可以终止启动流程。
- 不把客户端协议错误、上游网络错误和内部 invariant 统一成同一个响应。
- 不用“吞掉异常”“自动重试”代替错误策略；必须说明次数、边界和最终结果。

## 验证

覆盖成功、格式错误、认证失败、超时、取消、上游失败、部分 I/O 和重复关闭。审计报告应列出错误源、转换点、观察者和未覆盖路径。

## 相关 Skill

认证失败和重放见 `replay-audit`，敏感信息见 `leak-audit`，隧道 EOF/关闭见 `tunnel-audit`。
