# Agent 工程维护

## 目标

让项目事实可发现、规则可执行、验证可重复，并减少多套 Agent 配置漂移。只建设当前任务真正需要的能力，不用巨型提示替代源码、测试和机械检查。

## 权威入口

- `AGENTS.md`：项目共享规则和导航。
- `.claude/skills/`：唯一仓库级 skill 树。
- `docs/`：架构、计划、协议互操作和长期知识。
- `scripts/`：可重复的静态检查和维护工具。

兼容入口可以引用 `AGENTS.md`，但不得复制一份长期独立维护的完整规则。仓库不维护被 `.gitignore` 忽略的第二套 skill 正文。

## 工作流程

1. 选取真实任务或近期失败，定位阻塞在发现、实现、验证、评审还是恢复。
2. 从源码、测试、配置和现有文档收集证据。
3. 将缺口转成最小能力：索引、skill、测试、检查脚本或文档更新。
4. 为改动定义维护责任、触发条件、验证信号和删除条件。
5. 清理过时路径、重复规则、未引用模板和不能执行的命令。
6. 运行静态校验并重新读取入口，确保交叉引用有效。

## 约束

- 不使用 Python 脚本；仓库自动化优先 PowerShell 或现有工具链。
- 不自动构建、提交、推送、部署或启动长期进程。
- 不把用户级全局 skill 写成 Prism 的项目事实。
- 不创建第二个构建目录或被忽略的规则副本。
- 不覆盖用户未授权的现有文档或工作区修改。

## Skill 质量门

每个 skill 必须有小写短横线 `name`、明确 description、触发/不触发边界、当前项目事实、执行流程、验证和相关 skill。所有路径、符号和命令必须能在仓库中验证。

## 输出

报告能力改进、删除的重复项、可重复验证方式、仍需人工判断的边界和剩余风险。
