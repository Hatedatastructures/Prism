# Harness Engineering Principles

来源：OpenAI，《工程技术：在智能体优先的世界中利用 Codex》，2026-02-11。
https://openai.com/zh-Hans-CN/index/harness-engineering/

## 核心模型

- 人类掌舵：确定问题、优先级、验收标准与不可机械化的判断。
- 智能体执行：实现代码、测试、文档、CI、评审回应与维护工作。
- Harness 是使这种分工可靠的环境：上下文、工具、反馈回路和强制约束。
- 优化对象是人类时间与注意力，而不是单次生成代码的速度。

## 评估维度

| 维度 | 智能体应能做到 | 常见投资 |
| --- | --- | --- |
| 可发现性 | 找到任务相关的规则、架构和决策 | 简短的 `AGENTS.md`、索引化文档、版本化计划 |
| 可执行性 | 启动所需环境并运行标准工具 | worktree 支持、本地脚本、可复用技能 |
| 可观察性 | 以证据定位运行时问题 | 结构化日志、指标、追踪、浏览器/DOM 快照 |
| 可验证性 | 在无需人工转述的情况下确认结果 | 测试、检查、可重复的用户路径与验收信号 |
| 可约束性 | 不越过架构和质量边界 | 结构测试、lint、类型和模式边界 |
| 可维护性 | 让新知识和错误修复沉淀下来 | 决策记录、技术债台账、文档园艺与清理任务 |

## 反模式与替代

| 反模式 | 为什么会失败 | 替代方式 |
| --- | --- | --- |
| 巨型 `AGENTS.md` | 占用上下文、规则过期、无法机械检查 | 短目录 + 分层、索引化的仓库内知识 |
| 临时复制聊天上下文 | 不可发现、不可版本化、难以复用 | 把必要决策固化为文档、计划或规则 |
| 仅靠人工 QA | 人类注意力成为吞吐瓶颈 | 提供可运行、可观察、可验证的本地回路 |
| 反复给出同类评审意见 | 品味无法规模化 | 把规律编码为测试、lint、模板或工具 |
| 只在积债后集中清理 | 漂移会持续复制和扩大 | 定期的小型、自动化维护修复 |
| 用规定实现细节代替边界 | 抑制智能体在正确范围内搜索 | 强制不变量，允许局部实现自由 |

## 自主性门槛

只有当智能体已经能可靠地完成下列闭环时，才提高自主级别：验证当前状态、复现问题、实现变更、运行验证、收集证据、响应反馈、修复构建失败，并在需要判断时升级给人类。不要把某个仓库的自主性成果假定为可直接迁移的通用能力。

## 优先级启发式

优先投资于能同时带来以下结果的改进：减少人工上下文传递、缩短验证反馈时间、将一次性判断变为可执行约束、降低未来变更的认知负担。先修复真实任务暴露的缺口，再扩展平台能力。
