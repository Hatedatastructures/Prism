# Prism Preview 运维界面设计规范

版本：研究稿 v1，2026-10-17。用途：为下一轮重新设计提供统一依据。本文件没有宣称现有页面已经符合这些要求，也不是 ISO 或 WCAG 的符合性报告。

## 1. 规范的依据与边界

本次设计先回答任务、信息和操作问题，再确定视觉形式。原有 Corporate Clean 提示词、此前效果图及视觉调整记录只作为历史参考；它们不能替代以下任务约束。用户后续明确指示优先。

| 依据 | 性质 | 本项目如何使用 |
| --- | --- | --- |
| [ISO 9241-11:2018](https://www.iso.org/standard/63500.html) | 可用性定义与概念的国际标准 | 用具体用户、任务和使用情境评价结果，不以组件数量或技术新颖程度评价设计 |
| [ISO 9241-110:2020](https://www.iso.org/standard/75258.html) | 人与系统交互原则的国际标准 | 作为交互设计与评价框架；其官方摘要明确不覆盖美学和品牌设计，因此不能据此保证视觉好看 |
| [Jakob Nielsen 的可用性启发式](https://www.nngroup.com/articles/ten-usability-heuristics/) | 经验原则，不是强制标准 | 用于检查状态反馈、操作一致性、信息可识别性和错误恢复 |
| [NN/g 视觉层级](https://www.nngroup.com/articles/visual-hierarchy-ux-definition/) | 视觉设计指导 | 通过相对大小、对比和分组表达信息重要性，避免所有元素获得相同强调 |
| [NN/g 仪表盘设计](https://www.nngroup.com/articles/dashboards-preattentive/) | 运维与分析场景指导 | 区分即时判断和长期探索；定量比较优先使用可读的位置与长度 |
| [Carbon 排版](https://www.carbondesignsystem.com/building-blocks/foundations/typography/style-strategies)、[间距](https://www.carbondesignsystem.com/building-blocks/foundations/spacing/overview)、[数据表格](https://www.carbondesignsystem.com/building-blocks/core/components/data-table/guidelines) | 企业产品设计系统 | 参考任务型排版、稳定尺度、表格工具栏与渐进披露模式；不要求迁移组件库 |
| [WCAG 2.2](https://www.w3.org/TR/WCAG22/) | 无障碍成功准则 | 以 AA 为本项目目标，分别核对文字、键盘、焦点、颜色与目标尺寸等要求 |
| [GOV.UK 设计原则](https://www.gov.uk/guidance/government-design-principles) | 服务设计实践 | 从需求和实际数据出发，维持语言与行为一致，同时允许不同任务采用不同布局 |

ISO 部分依据官方公开摘要与标准目录，没有将草案或未取得的标准全文当成已核查条款。本文的像素值、布局建议、时间目标和 3D 使用条件均是 Prism 的设计约定，不是上述来源的强制原文。

## 2. 从任务推导界面

### 2.1 设计链路

```mermaid
flowchart LR
    A[使用者与场景] --> B[要完成的任务]
    B --> C[必须做出的判断]
    C --> D[判断所需证据]
    D --> E[能够采取的操作]
    E --> F[可核对的结果]
```

Prism 的主要用户是管理本机代理实例的运维人员。根据本次会话，核心任务包括判断接入能力、定位运行异常、管理账户策略与额度、诊断连接，以及核对操作结果。具体使用频率仍需在后续任务验证中确认，不能用设计者的猜测替代。

### 2.2 每个模块进入页面前的六项说明

1. 用户在这里要完成什么任务？
2. 看到这些信息后，可以做出什么判断？
3. 每个值来自哪个正式接口，代表什么范围和时间？
4. 信息变化是否要求用户现在采取行动？
5. 操作影响哪个完整身份的对象，执行结果在哪里确认？
6. 为什么适合放在这里，而不是列表、详情或分析页？

没有明确答案的信息先不进入首屏。缺少数据能力的需求进入能力清单，不用占位数值伪装实现。

## 3. 信息优先级与视觉层级

### 3.1 信息优先级

| 层次 | 判断依据 | Prism 中的例子 | 展示方式 |
| --- | --- | --- | --- |
| 立即判断 | 当前服务或判断能力受到影响，且有实际证据 | 预期接入入口故障；已证实的额度耗尽与拒绝；管理采样过期导致状态无法判断 | 主判断区：对象、原因、影响、采样依据、下一步 |
| 运行观察 | 需要观察负载、容量或变化，尚不能证明当前故障 | 吞吐与延迟变化、邮箱占用、账户消耗、计划排空进度 | 摘要、趋势、可比较清单 |
| 深入诊断 | 用于解释原因或核查细节 | Trace、原始事件、账本组成、配置差异、累计计数 | 详情、时间线、独立分析页 |

优先级由实际影响和紧迫程度决定。不同层次不能直接映射为红、黄、绿；数据未知也可能需要优先核对。

未配置 QUIC 不等于故障。计划排空不等于异常。累计拒绝非零不等于近期仍在拒绝。单个入口未就绪不等于所有代理能力中断。没有当前窗口数据时，不生成“近期新增拒绝”或失败率。

### 3.2 视觉层级

- 每个任务视图必须有明确的主要阅读入口。主入口可以是当前判断、核心图表或选中对象，取决于任务，不固定为大标题或大数字。
- 同时可见的摘要、图表、事件、表格和装饰不能获得相同的字号、面积、颜色和阴影强调。
- 首屏主要操作直接可见，次要操作退后，危险操作与常规查看操作区分。
- 相关信息靠近；不同任务组之间留出更大间距。卡片边界只在需要表达独立分组时使用。
- 层级须在灰度下仍成立。颜色补充状态，不能独自承担分组、选择和错误含义。
- 以真实长名称、地址、错误原因、缺测与零值检查布局，不能用整齐假文本证明设计成立。

## 4. 页面任务合同

| 页面 | 首要任务 | 默认直接可见的证据 | 按需展开或跳转 |
| --- | --- | --- | --- |
| 运行概览 | 判断当前是否需要介入，以及介入哪里 | 接入与观测可信度；已证实的当前问题；吞吐、连接分类、延迟与容量摘要 | 具体资源、原因、历史和操作结果 |
| 入口 | 判断实际提供哪些接入能力 | 配置与绑定地址、预期与实际状态、原因、状态时间 | 协议绑定、接入趋势、事件和配置 |
| Worker | 定位派发、积压和排空问题 | 接收状态、活动任务、邮箱占用/容量、有口径的拒绝与失败 | 连接、Task、持续变化和阻塞对象 |
| 账户 | 判断账户能否继续使用，并管理其策略 | 身份、分组、有效策略、当前速率、活动量、可用额度及周期 | 已结算/预约/异常占额、策略来源、连接和历史 |
| 用户组 | 管理默认策略，识别成员覆盖差异 | 成员数、默认值、继承与覆盖、明确范围的消耗 | 成员清单与归属变化，不冒充共享额度池 |
| 协议 | 比较接入和传输构成及异常 | 类型与实例、承载、活动量、统计范围、失败与延迟覆盖 | 实例差异、流量占比和关联资源 |
| Session/Stream/Task | 理解某条连接为什么卡住、失败或未退休 | 完整身份、来源/目标、账户、Worker、阶段、传输与关闭状态 | 时间线、子资源、原始事件和取消结果 |
| 事件 | 找到有影响的原因并定位对象 | 时间、级别、原因、对象、覆盖与丢失信息 | 完整上下文、同类频率和关联操作 |
| 资源分析 | 判断资源压力和增长是否可解释 | RSS、PMR、BytePool 的值、容量、变化与质量 | 时间关联、失败窗口和诊断对象 |
| 配置 | 理解并发布一次明确变更 | 生效版本、草稿差异、校验和持久化状态 | 变更范围、冲突、应用与回滚结果 |
| 操作中心 | 核实请求实际执行到哪一步 | 完整目标、受理时间、当前阶段、终态或未知原因 | 阻塞资源、失败详情与待核对结果 |

能力暂未提供时，显示能力与数据状态，不能仅为填满页面添加空图表。

## 5. 首页的主次规则

首页以运行判断为主要任务，长期分析通过时间范围和模块页进入。主判断区位置稳定，不因轮询突然移动；用户正在查看的对象与列表位置不能被自动更新替换。

| 情况 | 主要表达 | 支持信息与后续路径 |
| --- | --- | --- |
| 当前证据支持正常接入 | 当前服务能力及采集范围 | 负载、容量和近期变化，进入资源清单 |
| 存在已证实的接入或转发受损 | 受影响对象、原因和具体能力范围 | 未受影响能力、相关趋势、对象详情及事件 |
| 有明确的额度或策略阻断 | 哪个账户受到哪项约束 | 余额/限额/拒绝依据，进入账户策略或账本 |
| 数据过期、缺失或查询失败 | 当前无法可靠判断的范围 | 最近有效采样与核对入口，不维持旧绿色 |
| 计划排空或维护 | 预期动作与进度 | 剩余资源、阻塞原因、操作结果；不自动当成故障 |

“QUIC 入口尚未就绪”只是当前演示数据可讨论的示例，不是固定首页标题。问题列表的范围和排序必须有数据依据；只有已加载子集时，不能声称覆盖全实例。

宽屏优先给核心趋势和诊断清单更多宽度，次要分布与事件退为辅助区。响应式按任务阅读顺序重排，不能为了保持三列而缩小文字。首页不承担全部库存；列表摘要写明范围并提供查看全部。

## 6. 数据表达规范

### 6.1 指标必须有的数据说明

每项指标必须能核对名称、定义、单位、对象、时间、聚合方法、来源、可用性与覆盖；重要口径应直接呈现，其余通过可访问的说明展开。快照状态和时间窗口统计分别标识。

### 6.2 表达形式与口径

| 数据 | 优先表达 | 必须避免 |
| --- | --- | --- |
| 当前吞吐 | 同单位数字 + 时间折线 | 把累计字节当速率；用装饰像素柱取代连续变化 |
| 延迟 | 当前窗口 P50/P95/P99、样本量与趋势 | 平均多个 P95；把缺测画成 0；将首批写出命名为 TTFB |
| 账户额度 | 可用余额、周期、总额与账本组成 | 用有丢弃风险的观测流量重建额度余额；零等同不限 |
| Worker 邮箱 | 占用/容量、短期变化与拒绝证据 | 命名为 CPU 或完整执行队列；无容量时伪造百分比 |
| 协议构成 | 同口径的排序条形或比例条，显示分母 | 混合 TCP Session 与 UDP/QUIC；同类型实例重复计量 |
| 连接与租约 | 分别标注 TCP、QUIC、UDP、Mux、根连接租约 | 把不同实体合并成一个未解释的“连接数” |
| 内存与池 | 数值、已知容量、趋势与采样时间 | 单个 RSS 大数字直接得出内存泄漏结论 |
| 事件 | 标题、原因、时间、对象和覆盖 | 用单行省略隐藏原因；把缓冲区覆盖伪装成无事件 |
| 操作 | 受理、执行、终态、未知与中断 | 网络超时等同失败；已受理等同已完成；盲目自动重发 |

上述领域规则沿用本项目已确定的业务口径，是 Prism 的约束，不声称源于通用视觉设计系统。

定量图表优先使用位置与长度便于比较；颜色用于区分类别和提示。该选择参考 [NN/g 的仪表盘定量表达说明](https://www.nngroup.com/articles/dashboards-preattentive/)。比例图与趋势图不能为造型随意更换。

所有图表要求：单位与时间范围清楚；系列可通过线型或文字区分；缺测断开；tooltip 可读；空/过期/不支持有明确状态。平滑曲线、纵轴截断和聚合均须有合理依据，不为了视觉整齐改变数据含义。

## 7. 视觉与组件基准

以下是重新设计的项目起点。它们可通过真实页面验证调整，但调整须说明解决了什么任务或阅读问题。

### 7.1 视觉方向

沿用户最新参考图采用中性灰数据工作台：白色与浅石灰建立层次，深灰承担正文和数值，蓝色用于必要的交互强调，语义色仅表示相应状态。借鉴参考图的结构和材质，不复制电商字段、无意义增幅、像素装饰或低对比度细字。

| 角色 | 建议初值 | 使用约束 |
| --- | --- | --- |
| 页面 / 内容 / 辅助底 | `#fafaf9` / `#ffffff` / `#f3f3f0` | 背景层次克制，不层层套面板 |
| 正文 / 辅助文字 | `#202420` / `#62675e` | 辅助信息仍应清楚可读，不靠极浅灰制造层次 |
| 链接和交互蓝 | `#2d5da8` | 不将全部数值、图标和面板染蓝 |
| 分隔线 / 必要控件边界 | `#e4e4e0` / `#7b8176` | 装饰分隔线与识别控件必需的边界分开定义 |
| 成功文字与底色 | `#166534` / `#f0fdf4` | 同时有文字或符号 |
| 告警文字与底色 | `#92400e` / `#fffbeb` | 有明确对象与原因，不能整屏铺警告底色 |
| 错误文字与底色 | `#b91c1c` / `#fef2f2` | 表达真实故障或危险操作，不表示普通类别 |

已按 sRGB 公式核对上表指定前景/背景对：正文约 15.73、辅助文字约 5.22、链接约 6.48，三个状态文字对均高于 5.9；必要控件边界对白色约 4.00。它们不是对任意叠加背景、深色主题或完整页面的合规承诺，实际组合仍须复核。

### 7.2 排版与密度

| 角色 | 项目基准 | 目的 |
| --- | --- | --- |
| 页标题 | 24px，600 | 识别当前位置，不占据半屏 |
| 主要判断 / 核心数值 | 22–28px，600 | 仅为当前主要任务提供强调 |
| 区域标题 | 16–18px，600 | 建立稳定内容分组 |
| 正文 / 表格 | 16px / 15px，400–500 | 保持中文与密集数据可读 |
| 辅助说明 | 不低于 13px | 口径、原因、采样和单位可核查 |
| 常规控件 | 高度 36px；手机主要操作可增加到 44px | 易点击，避免为了密度缩成小图标 |
| 数据行 / 事件行 | 默认 44px / 68px，长内容可增长 | 库存便于扫描，原因保留完整 |
| 间距 | 4/8/12/16/24px | 同组小间距、跨任务大间距，不到处使用同一内边距 |
| 圆角 | 控件 8px、独立面板 8–12px、对话框 16px | 区分层次，不强迫开放分区套圆角卡片 |

中文优先使用已具备的 Noto Sans SC 与合适的系统中文后备字体，普通英文和数字可使用系统无衬线。锁定字体栈，并通过浏览器实际渲染核对；禁止压缩字形、过轻字重和无依据字距。数字按需要使用等宽数字，数值列右对齐、文本列左对齐，单位精度保持一致。

这里的字号与密度是针对用户偏好的项目约定。WCAG 并不规定所有网站必须使用 16px，也不规定所有表格必须是 44px。Carbon 的参考价值在于将排版和密度与使用任务相联系，而不是机械抄取其像素值。[Carbon 排版策略](https://www.carbondesignsystem.com/building-blocks/foundations/typography/style-strategies)

### 7.3 容器与动作

- 表格、图表、详情、时间线采用各自合适的结构，共享颜色、字级和交互语言；不能全部改成相同卡片。
- 边框、浅色标题带或留白择其必要者建立分组，不同时叠加厚边框、底色和重阴影。
- 普通内容不悬停浮起。按钮主要通过背景、边框、按压和焦点响应；不是所有图标都需要色块。
- 阴影优先用于真正覆盖内容的弹层，不能用到处增加阴影代替主次设计。
- 动效默认克制、短于或等于 200ms，支持减少动效；不能使数值或列表位置在操作中跳动。
- 只读摘要不能表现为按钮。可点击行、链接和独立动作要有清晰区别，复制不触发行选择。

GOV.UK 提倡行为和语言一致，同时允许场景差异；这支持统一设计语言下采用不同的页面结构。[GOV.UK 设计原则](https://www.gov.uk/guidance/government-design-principles)

### 7.4 组件与样式治理

- 语义颜色、字号、间距、圆角和密度共用一套版本明确的 token；页面不能随意发明接近但不同的数值。
- 替换样式时修改实际 owner 并移除被替代规则，不能不断追加最后一层覆盖来维持多套设计事实。
- 组件按表格、详情、趋势、时间线、表单和动作等职责组合；共享样式不意味着所有内容都套进万能卡片。
- 查询、领域转换、页面状态和展示分责；展示组件不直接解析 HTTP 字段，也不保存可由正式数据推导的第二套值。
- 先列出组件状态，再实现交互；对空、零、长内容、缺测、过期和错误分别提供可复现样例。
- 状态判断、单位转换和完整身份等行为由测试验证；对齐、主次、阅读动线与材质一致性通过真实页面人工验证。

React 官方的 [Thinking in React](https://react.dev/learn/thinking-in-react) 将组件层级、视觉状态和数据流作为实现思路。这能帮助维持界面结构，但不替代任务设计与视觉判断。本项目继续使用已有 React、Router、TanStack Query、Radix 和 Recharts，不以增加库作为设计进度。

## 8. 交互与可信状态

- 清单默认采用搜索/筛选/排序、表格或列表、精确对象详情；数据量超过当前页时显示范围和分页状态。
- 筛选只作用于已加载记录时必须明示，不能称为全局搜索。总数和排名不得由前端第一页冒充。
- URL 保留适用的时间和完整对象身份。目标不存在、已退出和过期分别说明，不选其他对象替代。
- 保留加载、查询失败、空集合、未采集、不支持、过期、未知与正常的区别；`null` 不转换成 0。
- 当前快照与历史区间分开表达。没有历史归属数据时，不把当前拓扑或连接清单冒充历史回放。
- 关键操作写明目标、范围和影响；受理后的反馈持续可查，失败或未知状态给出恢复路径。
- 账户策略、配置和账本调整分别显示正式版本及冲突，不能另建只存在于页面的配置事实。
- 实时事件支持暂停并保持阅读位置。自动刷新不抢焦点、不替换选中对象、不让行在指针下跳动。

## 9. 无障碍基线

本项目以 WCAG 2.2 AA 为目标。下列是重点检查项，不等于完整 AA 检查清单。

1. 普通文字对比度至少 4.5:1，大字号文字适用 3:1 的条件；不把 4.499 四舍五入为通过。[文字对比度](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)
2. 键盘可完成主要操作，焦点清楚可见；作者创建的固定栏或弹层不能将获焦控件完全遮住。[焦点可见](https://www.w3.org/WAI/WCAG22/Understanding/focus-visible.html)、[焦点不被遮挡](https://www.w3.org/WAI/WCAG22/Understanding/focus-not-obscured-minimum.html)
3. 指针目标按 2.5.8 核对至少 24×24 CSS px 或满足相应间距等例外。项目常规 36px 控件是更具体的实现选择。[目标尺寸](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)
4. 状态同时使用文字、符号或模式；名称、角色、选中状态和错误关联可由辅助技术识别。
5. 页面缩放、窄屏、弹层焦点恢复和减少动效单独检查；表格在自身区域处理二维内容。

`focus:ring-offset-2` 不是 WCAG 指定语法；2px 外描边和偏移是可选实现。2.4.13 Focus Appearance 属于 AAA，不能错误称为 AA 的统一像素规则。[焦点外观说明](https://www.w3.org/WAI/WCAG22/Understanding/focus-appearance)

`active:scale-[0.98]`、全卡片阴影、所有图标变蓝和指定圆角类也不是无障碍标准。是否采用，取决于任务、反馈清晰度与本项目视觉约束。

## 10. 3D 与特殊视觉的使用门槛

3D 是一种可选表达，不能作为“高级感”的替代指标。加入前须明确它帮助哪项任务，以及与二维表格/关系图相比的收益。

- 只表达真实对象、归属或逻辑层次；不把 Worker 暗示成物理主机，不虚构线路、地域与流量动画。
- 额度、速率、占比和容量等需要精确比较的数据保留二维数字、长度或位置表达。
- 提供可键盘操作的二维等价视图，处理低性能设备、窄屏和 WebGL 不可用状态。
- 不因 3D 占据首屏而推迟当前问题、原因、影响范围和操作入口。
- 无操作时不持续旋转或渲染，进入性能验证时测量实际成本，不承诺未经测试的帧率。

前面生成的设备连线图和棱镜雕塑图均未获得用户认可，不作为下一轮实现的视觉验收标准。

## 11. 重新设计的交付顺序

1. 建立任务与数据清单：确认主要判断、完整身份、接口、口径、覆盖与缺失能力。
2. 先画内容线框：至少覆盖正常、当前受损、数据不可信三种首页状态；不靠颜色和 3D 隐藏层级问题。
3. 进行任务检查：阅读者是否知道先看哪里、判断什么、下一步点哪里；先修结构再做视觉。
4. 固定字级、密度、配色、组件角色与状态规范，再做一个完整页面的视觉样稿。
5. 选择一条完整工作流实现，连接已有数据，验证真实长内容和错误状态。
6. 通过任务、视觉、无障碍与运行检查后扩展其他模块，保持页面各自职责。

不得以换一套组件库、增加一张效果图或让所有测试变绿替代上述过程。规范可以约束错误和不一致，视觉质量仍需要真实内容下的构图、细节检查和用户评价。

## 12. 验收与证据

以下时间和步骤是初始项目目标，需实测校准，不是外部标准规定，也不是已经通过的结果。

| 检查 | 初始目标与方式 |
| --- | --- |
| 首屏判断 | 在 5 秒内指出主要判断、证据范围及下一步；正常状态也应可解释 |
| 对象定位 | 从首页或资源列表不超过两次主要跳转到精确对象，目标缺失保持原身份 |
| 账户判断 | 可直接找到可用余额、当前速率、有效限制和下次重置，不从多个不明计数猜测 |
| Worker 诊断 | 能区分活动任务、Session、邮箱与并发，能定位计划排空的剩余资源 |
| 操作核实 | 能分清受理、执行、完成、失败、未知与中断，不将按钮成功反馈误当执行完成 |
| 视觉层级 | 灰度/缩小查看仍能辨认主要阅读入口；这种检查只作辅助，不能替代任务测试 |
| 阅读与密度 | 100% 缩放下检查中文实际字体、字重、长原因、数值对齐、单位与表格行 |
| 响应式 | 2265×1244、1920×1080、1440×900、1280×800、768×1024、390×844，记录 DPR 和缩放 |
| 无障碍 | 自动检查结合键盘、焦点和辅助技术人工核查，不能仅凭对比度扫描宣称 AA |
| 数据与运行 | 类型、转换、真实/演示边界、对象与分页、操作结果、缺测与状态分别验证 |

最终证据分别报告：功能测试、真实数据能力、视觉人工检查、任务测试、无障碍、性能。现有浏览器回归通过不代表本规范的层级、任务或审美已经验收。

## 13. 可直接用于后续任务的设计约束

> 为 Prism Preview 设计运维界面。先说明使用者的主要任务、所需判断、数据来源与口径，再组织信息和视觉。每个视图必须有清楚的主要阅读入口；重点由当前影响和任务决定。保持真实、缺测、过期、未知和不支持的区别，保留完整对象及操作结果。参考本文的中性灰视觉、字级、密度与组件约束，采用符合任务的表格、趋势、时间线或表单；不要均分信息、堆叠卡片或用装饰模型充当重点。先提交正常/受损/数据不可信的内容线框和任务验证依据，再实施完整页面。像素值是项目约定，无障碍要求依据 WCAG；不得将工具类当成设计原则，也不得声称规范或测试自动保证审美。
