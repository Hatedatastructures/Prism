# 管理 API 与 Web 控制台

Operations 是给管理员查询和操作正在运行的 Prism 的独立 HTTP 服务，不承载普通代理流量。Web 控制台是通过浏览器访问这组管理能力的可选静态页面。可以只启用 API，也可以在构建 Web 静态资源后同时启用网页。

可以这样区分：

- 代理入口（例如 SOCKS5 的 `127.0.0.1:1080`）接收代理客户端的网络请求。
- 管理入口（示例为 `127.0.0.1:9090`）给管理员或 Web 页面使用。
- Web 静态资源只是网页文件；只有 Operations 已启用且 `WebDirectory` 指向正确目录时，管理服务才能提供网页。

两种入口可以使用不同端口。除非已设计好访问控制和防火墙规则，管理入口应保持在 `127.0.0.1`，不要直接绑定到公网网卡。

## 启用 Web 页面

1. 在仓库根目录安装 Web 依赖并构建资源：

   ```powershell
   npm ci --prefix Web
   Get-Date -Format 'yyyy-MM-dd HH:mm:ss zzz'
   # 上海时间 08:00–22:00：
   cmake --build build --config Release --target PrismWeb -j 16
   # 上海时间 22:00–08:00：使用 -j 1。
   ```

   资源输出到 `build/Web/`，目录内应包含 `catalog.json` 和页面资源。

2. 在 Prism 配置中启用 Operations，并将 `WebDirectory` 指向该资源目录：

   ```json
   "Operations": {
     "Enabled": true,
     "Endpoint": "127.0.0.1:9090",
     "Timeout": 1000,
     "WebDirectory": "<Web 资源目录的绝对路径>"
   }
   ```

   `Enabled` 打开管理服务；`Endpoint` 是管理服务监听的地址和端口；`WebDirectory` 是生成资源所在的文件夹，不是 `index.html` 文件路径。相对路径按配置文件所在目录解析。上例使用占位路径，部署时替换成目标主机上实际存在的目录。

3. 启动 Prism 后，在本机浏览器打开 `http://127.0.0.1:9090/`。

未构建或未配置 `catalog.json` 时，Web 页面不可用，但已启用的 Operations API 仍可独立工作。界面中的操作范围取决于服务端公布的 capability；未提供的能力会显示为不可用，不会由演示数据代替。

### API 和网页分别检查什么

如果管理页面打不开，按这个顺序检查：

1. Prism 是否正常启动，配置里的 `Operations.Enabled` 是否为 `true`。
2. `Operations.Endpoint` 的端口是否已被其他程序占用；如果浏览器在另一台设备，`127.0.0.1` 指的是浏览器所在设备，不是运行 Prism 的服务器。
3. 如果 API 能访问而网页打不开，确认 `PrismWeb` 已构建，`WebDirectory` 指向包含 `catalog.json` 和其他静态文件的完整目录。
4. 修改配置后确认运行中的进程使用了新配置。编辑磁盘文件本身不会自动改变正在运行的服务。

## 网络边界

示例将 endpoint 绑定到 `127.0.0.1`，只允许本机访问。保持此设置，除非已经为远程访问配置了适当的访问控制和网络边界；不要为了让浏览器能连上而直接绑定到所有网卡。

远程管理时，应由部署者明确决定如何认证管理员、限制来源并保护传输。不要仅靠“端口不常见”来保护管理服务，也不要在没有理解服务端能力和防火墙规则前将管理端口开放到互联网。
