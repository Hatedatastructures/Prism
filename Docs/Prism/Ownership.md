# 所有权与异步生命周期

异步操作必须说明谁持有对象、在哪个 executor 上运行、如何取消、半关闭如何传播、谁执行最终关闭，以及调用方怎样等待 drain。协议私有状态由协议模块拥有；跨模块共享的数据面使用 typed contract。

## 先理解几个词

- **Owner（所有者）**：负责让对象活着，并在合适时机关闭、释放它的人或对象。比如持有 socket 的 session owner。
- **Executor（执行器）**：决定异步工作在哪个事件循环/调度上下文中运行。它不是线程安全的万能锁；同一个 I/O 对象仍要按约定串行访问。
- **取消（cancel）**：通知正在等待的异步操作尽快结束。发出取消请求并不一定表示所有协程都已经退出。
- **半关闭（half-close）**：在 TCP 连接的一侧停止一个方向的数据发送，同时允许反方向的数据继续完成；它不等于立即销毁整个连接。
- **Drain（排空）**：先停止接受新工作，再等待已经开始的任务、响应或子流真正结束；到截止时间仍未结束时，由 owner 按明确策略报告或强制收尾。
- **最终关闭者**：唯一负责最终关闭 socket/连接等资源的 owner，避免两个模块各自认为对方会负责关闭。

普通的同步代码可以在函数返回时清理局部对象；异步代码会在 `co_await` 处暂停，函数表面上已经走到后面，但任务和资源可能仍在使用。因此，判断资源能否释放时要看任务是否真正结束，而不能只看“已经调用了 stop/close”。

## 挂起点与借用

- `co_await` 之后，重新确认引用、指针、迭代器和 span 指向的对象仍存活。
- detached 协程只能捕获具有足够生命周期的 owner；不得借用即将离开作用域的 session 或配置引用。
- allocator/memory resource 必须比使用它的容器和对象活得更久。由 owner 提供资源，不在调用侧猜测池的生命周期。
- 一个 I/O 对象只由其规定的 executor/strand 串行访问。不得在协程里同步阻塞 socket、DNS、sleep 或等待 future。

例如，协程挂起前拿到某个容器元素的引用，挂起期间另一个任务可能改变容器；恢复后这个引用就可能不再有效。安全做法是挂起后重新从仍存活的 owner 读取所需对象，而不是假设旧引用一直有效。

## 关闭次序

关闭通常分成请求关闭、取消尚未完成的 I/O、传播写半关闭、等待活动任务和子流 drain、释放底层资源。收到关闭请求不等于资源已经退休；只有真实 owner 完成并报告 drain，调用方才能释放依赖它的状态。

应用启动失败由启动事务回滚已创建的 owner；运行期停机由 Application 协调 Runtime、Boundary、协议服务和 Operations 的关闭。各协议仍拥有自己的 wire/session 清理，不把协议关闭逻辑塞进 Application。

一个常见的关闭顺序可以理解为：先关入口，不再接收新连接；再取消正在等待的 I/O；协议按自己的规则发送剩余响应并传播半关闭；owner 等待活动任务和子流 drain；最后关闭底层 socket 并释放关联状态。具体协议可以有不同细节，但调用方必须能知道失败发生在哪一步以及谁仍然持有资源。

## 接口检查

新增或修改公共异步接口时，记录输入是借用还是转移、结果/错误形状、取消和半关闭行为、最终关闭者以及 executor。函数参数通常不超过两个；复杂边界参数应有真实领域语义。
